# Full-release quality and reproducibility

| File | Evidence |
|---|---|
| `manual_qc.csv` | Author review of all five views in 335 source-volume series; all accepted |
| `release_validation.csv` | Source-volume retention and the reconciliation of 2,244 targets to 2,229 released records |
| `unused_coordinate_targets.csv` | The 15 coordinate targets without a released paired record, identified by source volume and one-based target index |
| `qc_summary.json` | Crop/coordinate reproduction, file checks and the four validation steps; `supporting_checks` preserves eight merged reports, including the complete retrieval-verification JSON and all ten fold-pair comparisons with their original SHA-256 values |
| `figure_provenance.csv` | Figure record IDs, display settings and the stated verification status |
| `orientation_events.csv` | Per-view transformation provenance |
| `PROVENANCE.md` | UID/header normalization, final orientation and the relation between scored inputs and current files |

All 14,044 imaging and coordinate-file rows are indexed in the separate dataset's `metadata/files.csv`, including consolidated `qc_` fields. The original tables are preserved in `metadata_snapshot/`. Imaging and source-coordinate bytes were not modified by this reorganization. Crop checks evaluate extraction from arrays; coordinate-reading differences evaluate detector-centre localization.

Paths embedded in unchanged DICOM DerivationDescription fields describe the earlier release layout. In particular, the historical `validation/orientation_events.csv` now resolves to `validation/release_qc/orientation_events.csv`; the files themselves are not reserialized to edit that historical text.

In `qc_summary.json`, `supporting_checks.retrieval_verification.report` preserves all fields of the retrieval check. `supporting_checks.partition_overlap_check.rows` contains the ten fold-pair comparisons; `original_csv_utf8` retains the exact CSV text. `original_path` identifies the source before consolidation, not a separate downloadable file.

`supporting_checks.scoring_input_bridge.report` in `qc_summary.json` preserves all scoring-input bridge fields and its original SHA-256. The separate bridge file is no longer distributed.


## Data locations

Images and current consolidated metadata are in the separate [Zenodo dataset](https://doi.org/10.5281/zenodo.24156428) (version 1.0.0; CC BY 4.0; open-download access policy). Extract `paired-radiograph-cbct.zip` and use its `paired-radiograph-cbct/` directory as the dataset root. Paths beginning `metadata/` or `source_cbct/` refer to that dataset root. Validation paths refer to this code repository. Pre-consolidation metadata are preserved in `../release_qc/metadata_snapshot/` for interpreting historical input fingerprints. Current file QC, UID normalization and radiograph provenance fields are consolidated into dataset `metadata/files.csv` (`qc_`, `uid_`, `provenance_`); group fields and complete group-to-animal links are retained in dataset `metadata/metadata.csv`.

## Coordinate-target reconciliation

The 335 released source volumes contain 2,244 coordinate targets. Unique crop-origin and retained-dimension matching links 2,229 targets to released paired records; 15 targets in 11 source volumes have no released paired record. `release_validation.csv` gives the source-volume totals, and `unused_coordinate_targets.csv` identifies the 15 unused targets. The table uses one-based coordinate-target ordinals, not historical crop filenames or retained-crop ordinals.

Columns are `source_volume_id`, `coordinate_target_index` (one-based), `board_target_0_cm` and `board_target_1_cm` (in coordinate-file order, centimetres), and `release_status` (`not_released`). It records final-release membership; it does not infer undocumented exclusion reasons from historical file actions.

The earlier deletion-action snapshot was generated by replaying a working-directory log and did not establish final-release target membership. It is no longer used as the release exclusion list. Historical snapshots are preserved in prior code versions; imaging data and scientific validation results are unchanged.
